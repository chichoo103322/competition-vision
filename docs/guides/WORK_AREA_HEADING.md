# STM32 工作区到站转向对接

2026-11-03。以下约定来自本次电控方案；尚未进行新版整车运动验收。

## 配置与坐标

两区使用同一照片同向地图：左下原点、右 +X、上 +Y，单位 mm/degree，逆时针为正。树莓派 profile 必须显式设置 `work_heading_mode_enabled: true`，与主控开启配置一致；关闭兼容旧固件时双方同时改为 false。路线中至少有一个 101～108 工作点时整条路线激活工作区模式；没有这些点的普通路线仍按每点报文 yaw 执行。

工作目标由 `wrap_deg(initial_pose.yaw_deg + offset)` 计算。偏角始终相对路线初始地图航向，不累计、不使用 IMU 原始角。Pi 保留兼容报文 yaw，并在本地 JSON 中记录 `travel_yaw_deg`、`expected_work_yaw_deg`；V1 帧格式、CRC、单位、握手、消息类型均未扩展。

| 工作区 | work_id | 相对起始偏角 | 起始 +90° 时实际工作航向 |
|---|---:|---:|---:|
| 二维码 | 101 | +90° | −180°（等价 +180°） |
| 原料第一次 | 102 | −90° | 0° |
| 粗加工第一次 | 103 | +90° | −180°（等价 +180°） |
| 暂存第一次 | 104 | 0° | +90° |
| 原料第二次 | 105 | −90° | 0° |
| 粗加工第二次 | 106 | +90° | −180°（等价 +180°） |
| 暂存第二次 | 107 | 0° | +90° |
| 回启停区 | 108 | 0° | +90° |

第一段保持起始航向；后续行驶保持上一工作站航向，普通折线点不触发 Pi 转向。到工作点后 STM32 自行转到该站工作航向，Pi 不插入恢复航向点或额外转向命令。混合路线的未知工作编号到站使用其报文 yaw。

## 到站与放行

`RUNNING/phase=5` 是连续行驶，`RUNNING/phase=6` 是到站原地转向。phase 6 继续查询状态，不检查尚未完成的工作角、不扫码、不模拟驻留、不发送 WORK_DONE。每个路线号/点索引的转向最多等待 70 秒（60 秒主控上限 + 10 秒余量），同时保留整轮执行截止时间；默认整轮 600 秒。转向计时不会被重复状态重置。

只在 `WAIT_WORK/phase=4` 校验路线号、点数、零起始点索引、work_id、故障、目标 XY 和实际工作航向。位置容差仍为 8 mm，角度容差仍为 2°。误差为 `wrap_deg(reported_yaw - expected_yaw)`，180°/−180°等价；错误位置、错误朝向、FAULT、取消及真正超时继续尝试 STOP。串口中断时不能保证 STOP 到达。

本次二维码 `(350,1197,179.16°)` 对目标 `(350,1200,−180°)`：位置差 3 mm、角差 −0.84°，通过；相同位置回报 90°仍拒绝并停车。

异步 EVENT 只留作诊断，作业以匹配 STATUS 确认的 WAIT_WORK 启动。普通 ARRIVED/POINT_DONE 不触发作业。正式入口对 `(route_id, point_index)` 只调用一次 `on_work(client,status)` 启动作业；返回 None 后仅调用可选的 `poll_work(client,status)` 查询真实结果。返回 True 才成功放行，False 失败，缺真实结果则继续等待并最终超时；不要依赖旧版反复调用 on_work 的行为。status 包含 work_key、work_first_entry、expected_work_yaw_deg。比赛后端可实现 `poll_work`，不得另开串口抢读。

底盘测试仍明确标注 `test_mode=chassis_route_dry_work`，姿态校验通过后才开始 2 秒模拟作业。重复 WAIT_WORK 不重复启动或重置计时；已确认放行的重复消息不再次发送 WORK_DONE。人工目视方向测试可配置 `test_ignore_turn_obstacles=true`，持续跳过原地转向扫掠与障碍/禁行区相交检查；平移外廓、场地边界、规划中心线路径、控制状态和到站姿态仍检查。正式路线禁止该例外，示例默认false。

成功报文仍为 `0x13` + `<IHBB>`：当前 route_id、**零起始 point_index**、success=1、reserved=0。二维码示例 point_index=1，不能填 work_id=101。必须得到匹配请求的 ACK code=0、正确路线/索引且无控制器故障，拒绝或错误 ACK 会进入原保护。

## 路线审核与可视化

按初始/上一工作站航向检查每条平移段的实测前后左右矩形外廓；工作点检查到达航向到工作航向的完整旋转。平移采样间隔 ≤5 mm并额外膨胀 3 mm；旋转采样间隔 ≤1°并按最大角点位移额外膨胀，覆盖采样间隔。恰好180°的转向保守覆盖两个方向。矩形包含雷达突出板的最大外廓，可能比只在车身中部突出的真实板形保守；会减少可用净空。没有实测 footprint 的旧路线仍使用配置圆形余量，不能视为本车尺寸验收。

沿用中心线占据格/静态禁区检查；新增外廓与转向检查会拒绝旧路线潜在冲突，不因为历史曾跑通而跳过。不会修改雷达驱动、采集、定位或障碍证据。若固定工作站本身旋转范围冲突，仅换站间折线无法解决，需新的现场扫描或后续标定工作站位置。

本次复核 Pi 保存的 route_id=1793707732、20点旧计划：原料第一次工作点 photo `(1200,350)` 转向范围与历史占据格13交叠，故不能用此旧快照做新版实车净空结论。此为包含右侧板的保守矩形审核，未实车重扫/测量。

`prepared_live.json`、执行状态日志、`ElectricalClient.last_upload_review` 及单次测试输出保存报文 yaw/行驶车头/工作航向。服务在同目录生成 `direction_review.html`，单次工具在结果文件旁生成同名 HTML，表格显示三种航向及动作顺序。雷达网页的中心线预览不是底盘姿态审核；以此路线审核表为准。

实车尺寸以2026-11-03最新用户测量为准：车身长286mm、总宽296.28mm，右侧雷达安装板在前后中部突出；较早总宽294mm测量已过期。Pi profile `right_mm=167.78` 仍是外接矩形近似，实际板的纵向尺寸尚未单独标定。
